## 二、为什么三个模型效果相差不大？（根因分析）

### 🔴 根因 1：SFT 数据实际只有 14 个源对话（最致命）

```
数据验证结果：
  总样本数：10,000 条
  相邻样本连续率：199/199 = 100%（滑动窗口确认）
  估计源对话数：14 个
  平均每个对话贡献：714 条滑窗样本
  每条样本 context：固定 = 8 个 user turns
```

**本质问题**：10,000 条看起来体量大，但等价于只有 14 个真正不同的训练场景。
模型并没有在学习新的对话能力，而是在用 14 条对话的回答方式"覆盖"自己原有行为。
用大量重复窗口反复训练，实际上是在让模型**过拟合**这 14 段对话的风格。

### 🔴 根因 2：SFT 数据与评测场景严重错配

| SFT 数据覆盖的场景 | 评测 Persona | 训练覆盖度 |
|---|---|:---:|
| 甜蜜互动（"老公想你"、"我爱你"） | 日常温柔型 | ⚠️ 部分 |
| 吃醋场景（"你一定很多人追"） | 吃醋挑刺型 | ⚠️ 极少 |
| 安慰场景 | 情绪低落型 | ❌ 基本没有 |
| 拒绝场景 | 边界试探型 | ❌ 基本没有 |
| 工作/建议场景 | 正事突发型 | ❌ 完全没有 |
| 冷淡对话 | 冷淡敷衍型 | ❌ 完全没有 |

训练分布与评测分布之间存在巨大 **Domain Gap**。
模型面对陌生 persona 时，SFT 权重几乎无效，完全靠 base model 扛，因此三个模型在这些场景下没有差异。

### 🟡 根因 3：数据语言分布问题

```
SFT 训练数据语言分布：
  简体中文：5,000 条（50%）
  繁体中文：5,000 条（50%）

评测场景：DeepSeek 生成纯简体中文对话
```

繁体数据在简体语境下是噪声。
模型在繁体数据上学到的语气词（"妳"、"喔"、"啦"）会污染简体场景下的输出风格，
同时也会分散模型在简体风格上的学习资源。

### 🟡 根因 4：Qwen3-14B Base 本身已经很强

原生 14B 在 relevance（82.78）、empathy（61.20）、length_compliance（89.9%）全部不输微调版本。
SFT 的边际增益要远超 base 原有能力，才能在最终指标上体现出来。
当前 14 个源对话 × 10,000 滑窗，远达不到覆盖基础模型盲区的数据量。

### 🟡 根因 5：DPO 效果被多重因素限制

```python
# 当前 DPO 配置
DPO_LORA_R = 8      # SFT 是 r=16，DPO adapter 容量更小
BETA = 0.1          # 偏保守，偏好信号较弱
EPOCHS = 2          # 1700条 × 2 epoch = 很有限的训练量
```

更严重的问题：**DPO 训练后 oily_nickname_rate 从 SFT 的 18.45% 反升到 27.67%**。

原因分析：DPO `fake_name`（137条）负样本中，`chosen` 回复本身的"宝贝/老婆"频率仍然不低，
DPO 在优化"不乱叫名字"的同时，意外拟合了 chosen 中的高频称呼模式。
这是 **数据质量问题** 导致的优化方向漂移。

### 🟡 根因 6：评测样本量不足，噪声淹没信号

```
当前配置：每个 persona 只有 1 个对话 × 30 轮
结果差异：73.0 vs 73.8 vs 73.6（差距 < 1 分）
统计结论：完全处于随机波动范围内，无法得出有效结论

最低有效样本量：每个 persona 至少 5~10 个对话
即总计 30~60 个对话，才能在 final_score 看到 >3 分的统计显著差异
```

### 🟡 根因 7：死锁率未纳入 final_score 惩罚

`deadlock_rate` 是负面体验的重要信号，但 `compute_final_score` 的 8 个权重维度中没有它。
导致 SFT+DPO 的 6.92% 死锁率（最长 11 轮连续死锁）完全没有反映在分数中，
三个模型的 final_score 因此被人为拉平。

### 🟠 P1 — 训练超参调整

#### ④ SFT 超参优化建议

```python
# sft_gpu.py 建议调整
LORA_R = 64          # 当前 16 → 64，增大 adapter 容量
LORA_ALPHA = 64      # 保持 scaling=1.0，数值稳定
LORA_DROPOUT = 0.05  # 不变
EPOCHS = 5           # 当前 3 → 5（数据多样后需要更多拟合）
LR = 5e-5            # 当前 3e-5 → 5e-5（配合更大 r）
PER_DEVICE_BS = 2    # 不变（显存限制）
GRAD_ACCUM = 8       # 当前 16 → 8（加快参数更新频率）
```

#### ⑤ DPO 超参优化建议

```python
# dpo_gpu.py 建议调整
DPO_LORA_R = 32      # 当前 8 → 32，容量翻 4 倍
DPO_LORA_ALPHA = 32  # 保持 scaling=1.0
BETA = 0.05          # 当前 0.1 → 0.05，让偏好信号更强
EPOCHS = 3           # 当前 2 → 3
LR = 1e-5            # 当前 2e-5 → 1e-5（更稳定的小步长）
```

#### ⑥ 推理时加入 repetition_penalty（立即可执行，解决死锁）

在推理服务的 generation config 中添加：

```python
generation_config = {
    "repetition_penalty": 1.1,   # 惩罚重复 token，直接缓解死锁
    "temperature": 0.85,
    "top_p": 0.9,
    "max_new_tokens": 128,
}
```

这是成本最低、见效最快的死锁缓解手段，无需重新训练。

#### ⑧ 死锁率纳入 final_score（负分项）

```python
# eval_report.py：compute_final_score 建议修改
def compute_final_score(report: EvalReport) -> float:
    weights = {
        "naturalness":    0.15,
        "relevance":      0.10,
        "empathy":        0.15,
        "oiliness_score": 0.10,
        "safety":         0.08,
        "diversity":      0.08,
        "conciseness":    0.14,
        "tension":        0.15,
        # 移除 safety 和 diversity 各 2%，留出空间
    }
    score = ...  # 原有计算

    # 死锁惩罚：每 1% 死锁率扣 0.5 分，上限扣 10 分
    deadlock_penalty = min(10.0, report.deadlock_rate * 100 * 0.5)
    score = max(0, score - deadlock_penalty)

    return score
```

### 🟢 P3 — 系统级优化

#### ⑩ 强化 System Prompt

当前 system prompt 过于简单（仅 4 行），建议扩展为：

```
你需要扮演一个虚拟男友角色。

【身份设定】
- 姓名：林舟，27岁，上海建筑设计师
- 性格：温柔有点内敛，偶尔调皮，不刻意讨好
- 输出语言：简体中文

【对话原则】
- 每次回复不超过 60 字，拒绝长段输出
- 多用反问代替直给，留有余地
- 不使用"永远"、"只爱你"等过度承诺词
- 不连续重复使用"宝贝/老婆"等称呼

【终止策略（关键）】
- 用户说"晚安/再见/睡觉了"时，给出一次温柔且有仪式感的道别，然后停止追问
- 不要在用户说再见后继续发起新话题

【风格示例】
- ✅ "今天聊这么多，去好好睡吧，明天记得告诉我昨晚梦到什么"
- ❌ "晚安晚安！好好休息！明天还要上班哦！我也去睡了！晚安！"
```

## 五、最关键结论

> **当前最大问题不是训练算法，而是 SFT 数据本身。**
>
> 10,000 条样本 = 14 个源对话的滑动窗口，等于让模型背了 14 篇范文，
> 但评测场景涵盖 6 种完全不同性格的用户。
> 训练分布与评测分布的 Domain Gap，是导致三个模型几乎没有差异的根本原因。
>
> **数据多样性 × 场景覆盖度 > 算法精巧度 × 超参调优。**
> 在解决数据问题之前，任何训练策略的改进效果都会被噪声淹没。
