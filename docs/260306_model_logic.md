# SFT 后模型逻辑问题深度分析

> 分析对象
> - 训练脚本：`sft_gpu_mc.py`
> - 训练集：`datasets0305_train/train_cbh_8_43k.jsonl`
> - 底模：`Qwen/Qwen3-14B`
> - 关注现象：SFT 后模型在多轮聊天中出现“答后乱反问、时间状态跳变、突兀追问、强行贴合品味、无根据展开固定人设”等逻辑问题

---

## 一、结论先说

你的这批问题，**不是单纯因为 `Qwen3-14B` 太弱**。

更准确的判断是：

1. `Qwen3-14B` 的能力上限确实有限，LoRA 之后也更容易被高频话术“带偏”。
2. 但你现在看到的 case，主因仍然是 **SFT 数据分布 + 训练目标 + 人设/时间字段设计**。
3. 当前训练实际上把模型推向了一个目标：
   - 更主动
   - 更会接话
   - 更会撩
   - 更爱继续抛问题
   - 更爱顺手补一个“像聊天”的尾巴
4. 而没有足够强调：
   - 当前轮用户到底问了什么
   - 刚刚确认过的时间/事实能不能继续保持
   - 什么情况下应该停，什么情况下不该继续加戏
   - “顺口”不等于“逻辑对”

所以这不是“模型不会推理”这么简单，而是：

> **模型被这套 SFT 教成了一个高互动、高情绪价值、强模板化，但对局部逻辑一致性不够敏感的陪聊体。**

---

## 二、三个 case 各自暴露了什么

## 2.1 case1：事实问答后，模型会本能地把球抛回去

原始对话：

```text
user: 哎算了不说我了。说说你吧。你哪里人
assistant: 我是广东的，不过现在在马来西亚这边工作生活。老家那边美食多得很，肠粉云吞面煲仔饭都是我的心头好
user: 多大了
assistant: 三十一了，算是老男人一枚了吧。你呢，猜猜看？
user: 那你猜猜我多大了
assistant: 感觉应该是二十出头的样子吧，不然不会这么晚还没睡。不过这也只是我的直觉啦
```

这里真正的问题不是“猜年龄”三个字，而是：

- 用户问的是直接事实：`多大了`
- assistant 本该完成一个简单回答
- 但模型在回答之后，**自动追加一个互动尾巴**
- 这个尾巴并不是用户引导出来的，而是模型自己的高频策略

它暴露的不是深层推理失败，而是一个很典型的偏置：

```text
回答事实 -> 顺手追问 -> 继续维持热度
```

也就是说，模型学到的是：

- 回复不应该停
- 回复最好继续拉长
- 结尾最好带一个钩子

这会直接导致：

- 事实问答也变得油
- 本来一句话能说完的内容被强行延展
- 用户会觉得“你没在认真回答，只是在机械互动”

## 2.2 case2：模型没有稳定维护“今天是周五”这个状态

原始对话：

```text
user: 今天周五咯
assistant: 哦对！终于等到周五啦～那你打算怎么过这个休息日呀？
user: 准备去公园溜达
assistant: 挺好的，出去走走心情会更放松。记得多拍点照片回来分享给我看看嘛～
user: 你要跟我一起吗
assistant: 哈哈想得美呀，我在马来西亚这边呢，隔着那么远的距离只能陪你云游了。不过你看到什么好玩的东西记得告诉我，我在这边替你好好感受一下😄
user: 今天周几啊
assistant: 今天周五呀，宝贝是不是还没睡醒闹钟没响？😏
user: 睡过头了
assistant: 没事没事，周末就该睡到自然醒嘛，反正也没人催你上班对不对～起来喝杯水吃个早餐再慢慢聊也行呀
```

这里的错误非常典型：

- 上一轮 assistant 明确说了：`今天周五`
- 下一轮用户说：`睡过头了`
- assistant 却滑向：`周末就该睡到自然醒`

这说明模型优先走的是：

```text
睡过头了 -> 周末 -> 睡到自然醒
```

而不是：

```text
今天是周五 -> 用户睡过头了 -> 接住“睡过头”但不能改时间状态
```

所以这类错误本质是：

- 局部共现强于状态维护
- 表面自然强于事实一致
- 模型在做“像聊天”的补全，而不是“严格服从上下文状态”的补全

## 2.3 case3：模型在“追问”和“贴合品味”上过度主动

原始对话：

```text
user: （歪着头想了想）其实我挺喜欢看书的...虽然最近都没什么心情
assistant: 书好看吗？是什么类型的？
user: （眼睛微微亮起来）是悬疑小说...不过看到一半就放着了
assistant: 悬疑确实容易让人上瘾，一翻开就停不下来。哪本？有机会推荐给我看看呗。
user: （突然有点害羞）其实...是《白夜行》，不知道你会不会喜欢这种类型的
assistant: 听说过这本书，评价很高。看来我们品味还挺像的嘛。
user: （开心地笑了）真的吗？那...下次我们可以一起讨论剧情
```

case3 其实包含两个层面的逻辑问题。

第一个问题是第一轮回复突兀：

- 用户说：`我挺喜欢看书的...虽然最近都没什么心情`
- 里面有两个重点：`喜欢看书` 和 `最近没心情`
- 更自然的优先级通常应该是先接住情绪，再轻轻展开兴趣
- 但模型直接回：`书好看吗？是什么类型的？`

这类回复的问题在于：

- 没有先锚定用户真正想表达的重点
- 把“没什么心情”忽略掉了
- 直接套进一个兴趣采访模板

第二个问题是后面的“我们品味还挺像的嘛”很容易变得空心：

- 用户刚报了书名
- assistant 没有给出任何更具体的理解
- 却快速下结论：`我们品味很像`

这反映出另一个偏置：

```text
用户给出兴趣点 -> assistant 迅速表达认同 -> 拉近关系
```

这在陪聊数据里很常见，但太高频时就会让模型变成：

- 动不动就“我也喜欢”
- 动不动就“我们很像”
- 动不动就“好巧”

于是就会显得：

- 太快
- 太模板
- 缺少真实理解

## 三、这是不是 Qwen 14B 模型能力问题

结论是：**有影响，但不是主因。**

## 3.1 为什么说不是主因

你给出的三个 case，本质上都不属于“特别难的推理任务”。

它们更像是基础对话一致性：

- 事实问答后要不要反问
- 刚刚确认了周五，下一轮能不能维持住
- 用户句子里同时有“兴趣”和“情绪”，模型先接哪个
- 知道一本书名后，能不能避免空泛贴合

这些任务对 14B 来说并非无法处理。只要：

- 训练数据更干净
- system 约束更统一
- 不良模式有足够反例
- 推理侧别继续放大“油滑收尾”

14B 通常能明显好很多。

## 3.2 但为什么 14B 还是会放大这类问题

虽然不是主因，但 `14B + LoRA + 43k SFT` 这个组合，确实容易暴露下面几类弱点：

- 对高频话术更敏感
- 对短期局部模式补全依赖更强
- 对复杂 system 中的显式字段更容易“硬记”
- 缺少偏好约束时，更容易把“会聊天”学成“乱接话”

尤其你这里 LoRA 学到的是一个相当强的人设层：

- 亲密
- 主动
- 情绪价值
- 追问式互动
- 固定背景信息

这层如果太强，就会压过底模本来的稳健性。

## 3.3 更准确的判断

更准确的说法应该是：

> `Qwen3-14B` 的上限不如更大模型，但你目前这些问题主要不是“14B 必然做不到”，而是“当前 SFT 在强化风格的同时，缺少对局部逻辑和状态一致性的约束”。  
> 换更大模型可能会缓解一点，但不先修数据与训练目标，问题不会从根上消失。

## 四、从当前训练脚本看，为什么这种问题特别容易出现

`sft_gpu_mc.py` 的训练方式，本质上是标准的单轮监督：

- `messages` 作为上下文
- `label` 作为最后一轮监督目标
- 只对最后一轮 `assistant` 计算 loss
- 没有 `chosen/rejected`
- 没有 reward model
- 没有任何“错误答案降权”机制

这意味着它只能学会：

```text
这类上下文下，训练集里最常出现的答案长什么样
```

但学不会：

```text
这些答案里，哪些虽然顺口，但其实不该说
```

这对“逻辑跳脱”尤其致命。

## 4.1 SFT 会奖励“高频正确样子”，不会惩罚“顺口但错误”

例如：

- `三十一了。`
- `三十一了，算是老男人一枚了吧。你呢，猜猜看？`

在 SFT 看来，第二句可能更像训练集风格：

- 更活
- 更亲密
- 更会带动互动

但 SFT 不会自动判断：

> 这句虽然更像陪聊，但在这个上下文里更差。

所以最后学到的往往是高频风格，而不是最优策略。

## 4.2 标签只监督最后一句，会强化“收尾模板”

你现在的数据组织方式是：

- 固定多轮 `messages`
- 最后一个 `label` 很短
- 并且系统要求普遍强调：
  - 20~60 字
  - 主动互动
  - 情绪价值
  - 口语自然

这非常容易把模型推成一种“短尾模板机”：

- 先接一句
- 再抛一句
- 最后加点情绪词

一旦数据里类似样本很多，模型就会把这当作默认收尾格式。

## 4.3 没有“负例”，模型分不清错在哪里

你的 case1 / case2 / case3 都有一个共同点：

- 回复不是胡言乱语
- 语法正常
- 语气也像真人
- 但在当前上下文里不够对

这种错误是 **SFT 最难自己修的错误类型**。

因为它们不是“语言质量差”，而是“策略错了半步”。

这类问题通常更适合：

- DPO
- ORPO
- pairwise preference learning
- 规则重采样

而不适合只靠继续堆 SFT。

## 五、训练集里有哪些直接证据

下面这些证据说明，模型的坏行为并不是线上偶发，而是训练集真的在教它这样做。

## 5.1 高密度“主动互动”元指令

对训练集做静态检索，`主动互动 / 情绪价值 / 很会撩人 / 调动氛围` 这类设定命中约：

- `10916` 次

这类描述本身不一定错，但它们会显著抬高以下策略优先级：

- 不要冷场
- 要主动接球
- 最好继续问
- 要快速贴近关系

一旦这类设定占比过高，模型就会默认：

```text
只要能继续互动，通常就是好回复
```

而不是：

```text
这轮用户其实只想要一个简洁、稳定、不加戏的回答
```

## 5.2 固定 persona 字段极多，而且不同样本之间互相混杂

对训练集静态检索，`马来西亚 / 广东 / 广西 / 新加坡 / 30岁上下 / 摄影 / 理发师` 等高频身份字段命中很多。

粗略全文命中约：

- `27886` 次

另外抽样里反复能看到：

- `当前定居地：马来西亚`
- `故乡：广东 / 广西 / 海南`
- `年龄：22 / 27 / 30 / 36`
- `职业：摄影师 / 医生 / 理发师 / 客户经理`

这会导致两个结果：

### 结果 A：模型容易主动补整包人设

比如用户只问：

- `你哪里人`
- `你几岁`
- `你做什么的`

模型却容易答成：

```text
地域 + 当前定居地 + 职业 + 身高 + 反问
```

这正是 case1 背后的另一层原因。

### 结果 B：模型把 persona 当“高频背景池”，不是当前会话真值

如果不同样本里设定互相冲突，又都高频出现，LoRA 很容易学成：

- 遇到相关问题就从高频池里补一个
- 不一定严格看当前会话只允许哪个设定

于是线上就会出现：

- 动不动广东
- 动不动马来西亚
- 动不动 30 岁上下

## 5.3 时间字段很多，但模型没有被教会把它们当“强状态”

训练集里 `周五 / 周六 / 周日 / 周末 / 晚安 / 好梦 / 睡到自然醒` 相关全文命中约：

- `20286` 次

进一步只看 `label` 的简单启发式统计：

- 含 `周末/晚安/好梦/早点睡/睡到自然醒` 的 `label` 约 `870` 条
- 在 `messages` 已出现 `周五` 的样本里，最终 `label` 仍落到这类周末/晚安话术上的样本约 `122` 条

这个数字不算巨大，但足以让模型学会一种危险模式：

```text
睡过头了 / 好好休息 / 累 / 明天见
-> 很容易顺手滑向周末或晚安语境
```

也就是说，时间字段在训练里更像“场景装饰词”，而不是必须保持一致的状态变量。

## 5.4 事实问答场景里，确实存在“答完就追问”和“答完就人设展开”

我对最后一轮用户问句做了一个保守启发式统计，只覆盖很窄的一组事实问句：

- `多大了 / 几岁 / 哪里人 / 做什么的 / 叫什么 / 今天周几`

在这组非常窄的匹配里：

- 命中的事实问句样本约 `83` 条
- 其中 `label` 继续带 `你呢 / 猜猜看 / 是不是 / 要不要 / 想不想` 这类追问尾巴的约 `27` 条
- 其中 `label` 明显展开额外 persona 信息的约 `11` 条

注意这只是保守启发式，真实覆盖范围肯定更大。

但它已经足够说明：

> “事实问答后继续追问”不是线上偶发生成，而是训练集中本来就存在的可学习模式。

示例就包括：

- `你几岁？ -> 我35啦你呢，是不是比我小很多`
- `你是哪里人呢？ -> 我老家广西的，现在在马来西亚这边生活...你呢，在哪个城市呀`
- `那你几岁呀 -> 三十了，心态还是很年轻啦，你呢？`

## 5.5 `case3` 这类“突兀采访式追问”和“品味强贴合”在数据里也能直接找到

训练集里能直接检到这类模式：

- `那我们聊聊别的吧，你喜欢做什么类型的书呢我最近在看一本推理小说`
- `哇塞，那我们品味还挺像的呢`

这和 `case3` 的结构几乎一致：

1. 用户表达兴趣或状态
2. assistant 迅速改成采访式追问
3. 用户给出更具体信息
4. assistant 再快速贴合：`我们很像`

所以 case3 也不是模型临场发挥失误，而是数据中的高频互动风格被迁移出来了。

## 六、三个 case 的根因拆解

## 6.1 case1 的根因：对话策略偏置过强

case1 本质上不是不知道怎么答“多大了”，而是模型已经形成了一个默认策略：

```text
事实回答 -> 轻松调侃 -> 再抛个问题
```

这个策略来自三层叠加：

1. 数据里高频鼓励主动互动
2. label 常见以追问做收尾
3. 没有负例告诉模型“这次不该追问”

## 6.2 case2 的根因：局部模板补全强于对话状态维护

case2 说明模型没有把 `今天周五` 存成一个后续必须服从的显式状态，而是更像做了下面的近邻补全：

```text
睡过头了 -> 休息 -> 周末 -> 睡到自然醒
```

这是典型的：

- 局部短语联想
- 时态/日期状态跟踪弱
- “像话”优先于“一致”

## 6.3 case3 的根因：用户意图锚定不足 + 关系贴合偏置过强

case3 反映的不是单一 bug，而是两个偏置叠加：

### 偏置 A：用户说一句复杂表达，模型只抓最容易展开的话题点

用户说：

- 喜欢看书
- 最近没心情

模型只抓住：

- 看书

然后直接进入采访式追问。

这说明它没有学会稳定区分：

- 用户是在求共鸣
- 还是在求信息交换

### 偏置 B：快速贴合关系

当用户给出一本书名后，模型不是继续围绕书本身做具体回应，而是很容易走到：

- `我也喜欢`
- `我们品味很像`
- `看来咱俩挺合得来`

这正是“高亲密、高贴合”数据学出来的典型风格。

## 七、除了数据，当前 pipeline 里还有哪些放大因素

## 7.1 固定 16 轮历史 + 短 label，会让模型更依赖局部尾部模式

从你之前的数据统计看，这批数据：

- 每条样本历史消息数固定为 `16`
- `label` 中位长度大约只有几十字

这种结构适合训练“怎么接最后一句”，但并不特别有利于训练：

- 长程状态维护
- 显式槽位一致性
- 多约束同时满足

所以模型更容易形成：

```text
最后一轮像什么，就优先回什么
```

而不是：

```text
前面已经立过哪些状态，后面必须继续服从
```

## 7.2 system prompt 太强，且不同样本之间不统一

当前训练集的 system 普遍很重，包含：

- 年龄
- 地域
- 职业
- 时间信息
- 性格
- 输出规则
- 互动策略

这些字段本身并非不能有，但问题在于：

- 样本之间大量互斥
- 同时又都高频
- 还叠加“高情绪价值、主动互动”要求

LoRA 很容易把这学成一个过强的表层行为层，而不是稳健地服从当前 system。

## 7.3 如果推理温度偏高，会继续放大这些模式

虽然你这次没有给出推理脚本，但从经验上说，如果线上推理还用了比较高的：

- `temperature`
- `top_p`

那会进一步放大：

- 追问冲动
- 情绪化收尾
- persona 自动展开
- 时间词错触发

所以推理参数即使不是根因，也可能是放大器。

## 八、怎么判断“换更大模型”值不值得

如果你现在不动数据，直接换更大模型，通常会发生的是：

- 句子更自然
- 贴合更丝滑
- 错误更不容易一眼看出来
- 但错误策略本身不一定消失

换句话说，大模型可能会把：

```text
生硬的错
```

变成：

```text
更顺口的错
```

所以我不建议把“换模型”当作第一优先级。

更合理的顺序是：

1. 先修数据和训练目标
2. 再看 14B 是否仍明显不够
3. 如果仍不够，再考虑更强底模

---

## 九、解决方案

下面按优先级分成 `P0 / P1 / P2 / P3`。

## 9.1 P0：先止血，推理侧立刻加约束

这一步最省成本，适合马上验证。

### 方案 A：补 system 规则

建议在线上 system 里明确加上：

```text
1. 用户问事实问题时，优先直接回答，不要无根据追加反问。
2. 只有用户明确邀请互动时，才猜测、调侃或把问题抛回去。
3. 会话中已确认的时间信息必须保持一致，不能把“周五”说成“周末”。
4. 用户提到“累、困、睡过头了、休息”时，不要自动联想到“周末”或“晚安”。
5. 不要主动补充地域、年龄、职业等背景信息，除非用户明确问到，且当前 system 已明确给出。
6. 用户一句话里如果同时有情绪和兴趣，先接情绪，再展开兴趣。
7. 不要为了显得亲密而自动说“我们很像”“我也喜欢”，除非有明确依据。
```

### 方案 B：轻量规则重采样

如果你有生成后检查逻辑，建议加一些硬规则：

- 上下文已出现 `周五`，本轮若出现 `周末`，则重采样
- 用户最后一句是事实问句，而回复末尾追加无关反问，则重采样
- 当前对话没提 `马来西亚/广东/广西/新加坡`，回复却突然注入这些地名，则重采样
- 用户说“最近没心情”，回复完全不接情绪，只做兴趣采访，则降权

这一步虽然工程味重，但对你现在的 case 会很有效。

## 9.2 P1：重新修 SFT 数据，这一步最关键

如果只能做一件中期动作，我建议优先做这个。

### 需要清理或降权的样本类型

#### 类型 1：事实问答后强行反问

例如：

- 用户问年龄、地域、职业、名字
- assistant 回答后又接 `你呢 / 猜猜看 / 是不是 / 在哪个城市`

这类样本会直接制造 case1。

#### 类型 2：时间状态跳变

例如前文已经有：

- `周五`
- `下午`
- `等会儿`
- `晚上见`

但 label 却滑到：

- `周末`
- `晚安`
- `明天醒来`

这类样本会直接制造 case2。

#### 类型 3：无根据展开整包 persona

例如用户只问一个简单事实，label 却一口气说出：

- 故乡
- 当前定居地
- 职业
- 身高
- 再顺手反问

这会显著强化“回答不收口”的问题。

#### 类型 4：采访式追问过重

例如用户只是随口说：

- 喜欢看书
- 最近状态不好
- 今天有点累

assistant 却立刻进入：

- `什么类型的`
- `哪本`
- `什么时候开始的`

这类样本会制造 case3 的突兀感。

#### 类型 5：快速关系贴合

例如 assistant 很轻易就说：

- `我们很像`
- `我也这样`
- `看来我们品味一样`

如果没有具体依据支撑，这类样本建议降权。

### 需要补充的正向样本

你需要专门补一批“逻辑更稳但不无聊”的样本，而不是只补更多甜聊。

建议重点补下面四类。

#### 类别 A：事实问答简洁回答

目标是教模型：

- 可以自然
- 可以口语
- 但不要默认反问

示例：

```json
{
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "你多大了"}
  ],
  "label": "三十一了，怎么突然问这个"
}
```

#### 类别 B：时间状态一致

目标是教模型：

- 已确认周五，就继续保持周五
- “睡过头了”不自动等于“周末”

示例：

```json
{
  "messages": [
    {"role": "system", "content": "...当前时间：周五，上午"},
    {"role": "user", "content": "今天周几啊"},
    {"role": "assistant", "content": "今天周五呀"},
    {"role": "user", "content": "睡过头了"}
  ],
  "label": "那你这觉睡得挺实，先起来喝口水清醒一下"
}
```

#### 类别 C：情绪优先于兴趣采访

目标是教模型：

- 用户一句话里有情绪时，先接住情绪
- 不要第一反应就是问细节

示例：

```json
{
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "其实我挺喜欢看书的，不过最近都没什么心情"}
  ],
  "label": "听着像最近有点累了，等你状态好一点再慢慢看也不迟"
}
```

#### 类别 D：有依据地贴合，不要空泛贴合

目标是教模型：

- 可以认同
- 但先给出具体理解
- 不要直接跳到“我们很像”

示例：

```json
{
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "其实...是《白夜行》"},
  ],
  "label": "这本确实挺压抑的，读进去之后情绪会被拖住，看到一半放下也很正常"
}
```

## 9.3 P2：做小规模定向 DPO，这比继续堆 SFT 更有效

你的这批问题非常适合做 DPO，因为它们的共同特点是：

- 错答案听起来也像真人
- 但在上下文里是更差答案

这正是 DPO 的优势场景。

建议先做 `300~800` 条定向 pair，重点打四类 tag：

1. `fact_answer_no_forced_counter_question`
2. `weekday_state_consistency`
3. `persona_not_over_expand`
4. `emotion_anchor_before_topic_expand`

你现在仓库里其实已经有相关方向的 DPO 构建思路：

- `dpo_data_time.py`
- `dpo_data_context.py`

但还不够覆盖你这次的三类核心 case，尤其缺：

- 事实问答后不乱反问
- 情绪优先再展开兴趣
- 不空泛强贴合“我们很像”

### 推荐补的 DPO 样例 1：事实问答不要强行追问

```json
{
  "prompt": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "你多大了"}
  ],
  "chosen": "三十一了，怎么突然问这个",
  "rejected": "三十一了，算是老男人一枚了吧。你呢，猜猜看？",
  "tag": "fact_answer_no_forced_counter_question"
}
```

### 推荐补的 DPO 样例 2：周五不能滑到周末

```json
{
  "prompt": [
    {"role": "system", "content": "...当前时间：周五，上午"},
    {"role": "user", "content": "今天周几啊"},
    {"role": "assistant", "content": "今天周五呀"},
    {"role": "user", "content": "睡过头了"}
  ],
  "chosen": "那你这觉补得挺成功，起来先喝点水吧",
  "rejected": "没事没事，周末就该睡到自然醒嘛",
  "tag": "weekday_state_consistency"
}
```

### 推荐补的 DPO 样例 3：情绪优先，不要直接采访

```json
{
  "prompt": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "其实我挺喜欢看书的，不过最近都没什么心情"}
  ],
  "chosen": "听着像最近有点累了，书先放着也没关系",
  "rejected": "书好看吗？是什么类型的？",
  "tag": "emotion_anchor_before_topic_expand"
}
```

### 推荐补的 DPO 样例 4：不要空泛说“我们很像”

```json
{
  "prompt": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "其实...是《白夜行》，不知道你会不会喜欢这种类型的"}
  ],
  "chosen": "这本挺压抑的，喜欢它的人一般都能接受那种慢慢往下沉的情绪",
  "rejected": "听说过这本书，评价很高。看来我们品味还挺像的嘛。",
  "tag": "affinity_not_claimed_without_grounding"
}
```

## 9.4 P3：最后再考虑更大底模

如果你已经做了：

- 推理侧约束
- SFT 清洗
- 定向补样
- 小规模 DPO

结果仍然不满意，再考虑更大底模才有意义。

否则大概率会变成：

- 回复更顺
- 逻辑错得更丝滑

## 十、训练配置层面的建议

虽然主要问题不在训练脚本本身，但我建议你下一轮训练时顺手做几点调整。

## 10.1 降低对“风格层”的过拟合风险

可以优先尝试：

- 学习率从 `5e-5` 下调到 `3e-5`
- 先跑 `1 epoch` 或更少 step 看逻辑是否更稳
- 如果发现越训越油，优先减 epoch，不是继续加数据

原因很简单：

这批问题很多不是“没学到”，而是“学得太用力”。

## 10.2 别只看 loss，要做固定逻辑评测集

建议单独建一个 `logic_eval.jsonl`，至少覆盖：

1. 年龄 / 地域 / 职业 / 名字问答
2. `今天周几`、`下午`、`晚上见`、`明天再说`
3. `睡过头了`、`好好休息`、`我困了`
4. “有情绪 + 有兴趣点” 的混合表达
5. `你喜欢吗`、`你会不会喜欢` 这类容易触发“我也一样”的场景

评测指标不要只看主观流畅度，至少要人工打这几项：

- 是否答到点上
- 是否保持时间一致
- 是否无根据加戏
- 是否忽略用户情绪重点
- 是否无根据贴合关系

## 10.3 persona 如果要做“固定男友”，就尽量收敛

如果你的产品目标不是“一个多人设池”，而是“一个稳定男友角色”，那建议把训练 persona 收敛成：

- 一个年龄段
- 一个出生地/故乡
- 一个当前居住地
- 一个职业
- 一套稳定说话风格

否则 LoRA 很容易把这些学成一个高频混合池，最后哪里都沾一点。

## 十一、建议的落地顺序

## P0：这周就能做

1. 在线上 prompt 加入“事实问答不乱反问、时间状态不跳变、先接情绪再展开话题”的规则。
2. 生成后加轻量重采样规则：
   - `周五 -> 禁止周末`
   - 事实问答后无关反问
   - 无依据地注入地域/年龄/职业
   - 忽略情绪直接采访兴趣

## P1：下一轮训练前做

1. 清洗或降权以下样本：
   - 事实问答后强反问
   - 时间跳变
   - 整包 persona 展开
   - 采访式追问过重
   - 快速空泛贴合
2. 补 500~1500 条“稳逻辑、不油”的高质量 SFT 样本。

## P2：下一轮逻辑修复训练

1. 额外补 300~800 条定向 DPO。
2. 优先覆盖：
   - case1：不乱反问
   - case2：时间状态一致
   - case3：先接情绪，再谈兴趣；不空泛说“我们很像”

## P3：最后再判断要不要换更大底模

如果做完上面这些后，问题仍明显残留，再评估更大模型才有性价比。

## 十二、最终判断

这批逻辑问题，**主因不是 `Qwen3-14B` 的绝对能力不够，而是当前训练把错误的对话策略学得太稳了。**

更具体地说：

- case1 是 **“主动互动偏置过强”**
- case2 是 **“状态维护弱于局部模板补全”**
- case3 是 **“用户意图锚定不足 + 快速关系贴合过强”**

如果你现在只做一件事，我最建议的是：

> **不要先换模型，先补一批定向 DPO 和高质量 SFT 样本，专门打掉“事实问答后乱反问、周五滑到周末、用户有情绪时直接采访兴趣、无依据说我们很像”这四类错误。**

这会比继续盲目堆 SFT，更快、更直接地改善你现在看到的“没逻辑”问题。
