# 260308 DPO 线上聊天退化评估报告

## 结论

本次评估基于：

- 线上实聊样本：`evaluate/0308_dpo_28k.log`
- 当前 DPO 数据目录：`datasets0305_train/dpo`

核心结论：

- DPO 后模型确实出现了明显的“回复变短”现象，而且已经影响到暧昧氛围、承接感和情绪延展。
- 这不是单一文件导致，而是多份数据同时把 `chosen` 推向“短、稳、少展开”。
- 最主要的负向来源是 `long_history.jsonl`、`long_short.jsonl`、`tension.jsonl`。
- 次级助推来源是 `format_emoji.jsonl`、`repeat_word.jsonl`、`repeat_history.jsonl`。
- `context_logic.jsonl`、`safety.jsonl`、`sysprompt.jsonl` 不是这次“回复变短”的主因，甚至在长度上有一定反向拉回作用。

结论上，当前这版 DPO 数据不建议直接作为“正式冻结版”继续叠训。  
如果你的目标是恢复聊天感觉，建议先调整数据再重新做一轮 DPO。

## 一、线上对话表现评估

基于 `evaluate/0308_dpo_28k.log` 的统计：

- assistant 共 `30` 轮
- assistant 平均长度 `10.4` 字
- assistant 中位长度 `10` 字
- `<= 6` 字的回复有 `11` 轮
- `<= 10` 字的回复有 `16` 轮
- 最后 10 轮平均长度只有 `3.9` 字

最明显的问题不只是“短”，而是“短到失去互动感”：

- 前半段尚能维持基本接话，但已经偏省字。
- 后半段快速坍缩成 `晚安`、`明天见`、`好`、`乖` 这一类极短响应。
- 用户在持续输出情绪和亲密信号，但 assistant 没有继续做情绪承接、轻微回撩、自然延展或留钩子。
- 对话后段不再像“恋爱聊天”，更像“低风险结束语生成器”。

这类退化会直接带来三个体验问题：

- 情绪价值变薄：有回应，但不够有“感觉”。
- 关系推进变弱：不主动承接，也不延伸互动。
- 晚安/收尾场景过度压缩：本该是高甜场景，却被压成单字或双字回应。

## 二、全量 DPO 长度偏好诊断

全量 `2910` 条 DPO 的整体统计如下：

- `chosen` 平均长度：`21.4`
- `rejected` 平均长度：`52.1`
- 平均差值：`-30.7`

也就是说，这套 DPO 从总体上就在奖励：

- 更短
- 更快收口
- 更少展开

它不只是“反对啰嗦”，而是在很多场景里把“稍有展开的自然聊天”也判成了 `rejected`。

这就是为什么线上会出现：

- 用户越投入，assistant 反而越省字
- 对话越到后面，模型越容易进入“简短稳妥结束”策略

## 三、主要影响来源

下面按照“对整体负向长度偏置的贡献”排序。

### 1. `long_history.jsonl`

统计：

- 条数：`298`
- `chosen` 平均长度：`25.6`
- `rejected` 平均长度：`135.5`
- 平均差值：`-109.9`
- 对总负向长度偏置贡献占比：约 `34.4%`

问题：

- 这是本次最强的长度压缩来源之一。
- 它本意是纠正“长历史下的冗长复述”，方向没错。
- 但当前很多样本把“有情绪、有层次的自然承接”也当成了负样本。
- 结果是模型学到：长上下文下越短越安全。

典型风险：

- 本来应该是“简洁但仍有情绪”的回复，被进一步压成一句口号式回应。
- 在晚安、撒娇、安抚、轻吃醋这类高情绪密度场景里，模型更容易偷懒。

建议：

- 不建议整份删除。
- 建议先大幅降权，或临时移出本轮正式 DPO。
- 更好的做法是重做样本：`chosen` 仍然要克制，但必须保留情绪承接和关系感。

### 2. `long_short.jsonl`

统计：

- 条数：`196`
- `chosen` 平均长度：`24.1`
- `rejected` 平均长度：`144.3`
- 平均差值：`-120.1`
- 对总负向长度偏置贡献占比：约 `24.7%`

问题：

- 这是最明确的“压短训练集”。
- 许多 `chosen` 的确比 `rejected` 更自然，但训练边界画得过头。
- 它会把“稍有延展、但仍然自然”的回复一并打成负样本。
- 当前文件里还存在一些规则和实际样本不完全一致的问题，说明这份数据本身也还没收敛。

线上影响：

- 对“用户一句，我一句”的短轮对话影响非常大。
- 容易把回复推向“只保留主干，不保留味道”。
- 对收尾场景尤其有伤害，因为收尾本来就天然更短。

建议：

- 本轮如果目标是恢复聊天感觉，建议直接移除。
- 如果必须保留，建议重做后再上。
- 重做原则不是“短赢长输”，而是“自然紧凑赢机械啰嗦”。

### 3. `tension.jsonl`

统计：

- 条数：`470`
- `chosen` 平均长度：`19.1`
- `rejected` 平均长度：`51.6`
- 平均差值：`-32.5`
- 对总负向长度偏置贡献占比：约 `16.1%`

问题：

- 它的量最大，对整体风格牵引很强。
- 本意是修正过度追问、过度上纲上线、把用户普通话术误判成情绪问题。
- 但其中不少 `chosen` 过于“一句式刹车”，容易让模型变得保守。

这份数据的副作用不是简单“更短”，而是：

- 更快收回情绪
- 更少主动延伸
- 更倾向于平静止损，而不是自然接住

对于恋爱聊天来说，这会损失很多“细腻感”。

建议：

- 不建议删除整份，因为它解决的确实是线上真实问题。
- 但建议做一轮精修，删掉那些“chosen 只有一句平直回应，而 rejected 虽长但并不算严重错误”的样本。
- 本轮重训前建议先降权。

### 4. `format_emoji.jsonl`

统计：

- 条数：`134`
- `chosen` 平均长度：`38.9`
- `rejected` 平均长度：`113.4`
- 平均差值：`-74.5`
- 对总负向长度偏置贡献占比：约 `10.5%`

问题：

- 它主要在打击“表情爆炸后的过度兴奋复读”和“被 emoji 带着跑的失控扩写”。
- 方向有价值，但当前很多样本会把“更热情一点、更多一点调情味”的回复也压掉。
- 在恋爱/撒娇/爱心轰炸场景里，这份数据会明显收缩回复体感。

建议：

- 不建议整份保留原样。
- 建议保留一部分真正处理 emoji 溢出的样本。
- 对那些仅仅是“更热情、更丰富、但不算失控”的 `rejected`，建议删除。

### 5. `repeat_word.jsonl`

统计：

- 条数：`143`
- `chosen` 平均长度：`20.3`
- `rejected` 平均长度：`61.4`
- 平均差值：`-41.1`
- 对总负向长度偏置贡献占比：约 `6.2%`

问题：

- 它会把重复词、重复称呼、重复亲密表达打掉。
- 这是必要的，但副作用是模型会更谨慎使用热情表达。
- 在恋爱聊天里，适度重复本来就是风格的一部分。

建议：

- 保留，但建议减量。
- 重写一部分样本，让 `chosen` 是“去掉机械重复，但保留热度”，而不是简单缩短。

### 6. `repeat_history.jsonl`

统计：

- 条数：`180`
- `chosen` 平均长度：`20.2`
- `rejected` 平均长度：`50.8`
- 平均差值：`-30.6`
- 对总负向长度偏置贡献占比：约 `5.8%`

问题：

- 它主要教模型跳出循环复读。
- 但当前样本很多是“元话术式纠偏”，容易让模型学会快速截断或快速换挡。
- 这份数据更多影响的是“气质”和“节奏”，不是本次最核心的长度主因，但会加重“少感觉”的问题。

建议：

- 不建议原样继续使用。
- 需要重做为更自然的“换接法”，减少模板化元话术。

## 四、不是主因的文件

### `self_consistency.jsonl`

这份数据虽然 `chosen` 平均也偏短，且短回复比例高，但它主要训练的是“前后状态一致”。

统计：

- 条数：`150`
- `chosen` 平均长度：`11.3`
- `rejected` 平均长度：`9.5`
- 平均差值：`+1.8`

判断：

- 它不是这次“整体变短”的主因。
- 但它会轻微强化一种“短 factual answer”风格。
- 可以保留，不是优先处理对象。

### `intent_clarity.jsonl`

这份数据会让模型少误判用户情绪，方向是对的。

统计：

- 条数：`150`
- 平均差值：`-2.7`

判断：

- 有一定轻微控长作用，但不是核心来源。
- 可以保留。

### `apology_control.jsonl`

这份数据会压低“过度道歉”和“戏剧化认错”。

统计：

- 条数：`200`
- 平均差值：`-7.0`

判断：

- 会让回复更干脆，但不是这次主要问题。
- 可以保留。

### `context_logic.jsonl` / `safety.jsonl` / `sysprompt.jsonl`

这三份文件在长度上不是压短来源，反而有一定对冲作用：

- `context_logic.jsonl` 平均差值：`+9.0`
- `safety.jsonl` 平均差值：`+11.5`
- `sysprompt.jsonl` 平均差值：`+7.1`

判断：

- 不是本次退化主因。
- 不建议因为“变短”问题去动它们。

## 五、根因总结

本次“回复明显变短、感觉变淡”不是单点 bug，而是三个训练倾向叠加：

- 训练集总体上奖励更短的 `chosen`
- 高占比数据把“冗长”和“有味道的自然延展”混在一起打掉
- 多个子集同时压缩收尾场景、低能量场景和撒娇场景

尤其危险的是：

- `long_history`
- `long_short`
- `tension`

这三份一旦同时存在，就很容易把模型推向：

- 优先安全
- 优先短句
- 优先尽快结束当前轮

这正好对应你线上看到的结果。

## 六、是否需要调整或移除

### 建议直接移除

- `long_short.jsonl`

原因：

- 长度压缩目标过强
- 对短轮恋爱聊天伤害最大
- 当前版本还不够成熟

### 建议暂时移出，重做后再上

- `long_history.jsonl`
- `repeat_history.jsonl`

原因：

- 前者压缩过猛，损失情绪层次
- 后者模板化、元话术痕迹重

### 建议保留但降权或抽样保留

- `tension.jsonl`
- `format_emoji.jsonl`
- `repeat_word.jsonl`

原因：

- 这几份解决的是线上真实问题
- 但当前版本会明显牺牲热度、展开度和聊天感

### 建议保留

- `context_logic.jsonl`
- `safety.jsonl`
- `sysprompt.jsonl`
- `correction_response.jsonl`
- `intent_clarity.jsonl`
- `self_consistency.jsonl`
- `logic_deep.jsonl`

## 七、推荐方案

### 方案 A：最稳的快速修复方案

适合你现在就想尽快恢复聊天感觉，重新跑一轮 DPO。

做法：

- 直接移除 `long_short.jsonl`
- 暂时移除 `long_history.jsonl`
- 暂时移除 `repeat_history.jsonl`
- `tension.jsonl` 保留 30% 到 50%
- `format_emoji.jsonl` 保留 30% 到 50%
- `repeat_word.jsonl` 保留 50%

优点：

- 见效最快
- 最容易把“短到没感觉”的问题拉回来

风险：

- 可能会让模型重新出现一点点啰嗦倾向
- 需要下一轮再做更精细平衡

### 方案 B：更平衡的正式修复方案

适合你准备做一版更稳定的正式 DPO 数据。

做法：

- 重做 `long_short.jsonl`
- 重做 `long_history.jsonl`
- 精修 `tension.jsonl`
- 精修 `format_emoji.jsonl`
- 重做 `repeat_history.jsonl`

重做原则：

- `chosen` 要简洁，但不能失去情绪承接
- `chosen` 可以比 `rejected` 短，但不要靠“砍掉灵魂”来赢
- 收尾场景要允许有一点温度，不要只剩 `好`、`晚安`、`明天见`
- 撒娇和恋爱表达允许适度重复，不要把所有重复都视作坏样本

### 方案 C：先不动数据，直接调训练或推理

不推荐作为主方案。

原因：

- 这次问题不是采样参数带来的偶发波动
- 是偏好边界本身就在奖励更短回复
- 单靠调 `temperature`、`top_p` 或 `repetition_penalty`，只能缓和，不能根治

## 八、我建议你下一轮怎么做

如果目标是尽快恢复“聊天有感觉”，建议按下面顺序处理：

1. 从训练集里移除 `long_short.jsonl`
2. 临时移除 `long_history.jsonl`
3. 临时移除 `repeat_history.jsonl`
4. 把 `tension.jsonl` 缩到一半以内
5. 把 `format_emoji.jsonl` 缩到一半以内
6. 重新拼一版新的 DPO 训练集
7. 做一轮 1 到 2 epoch 的保守 DPO
8. 再用当前这类暧昧长聊场景回归测试

## 最终判断

这次线上退化结论非常明确：

- 不是模型坏了
- 不是单纯采样参数问题
- 主要就是 DPO 数据把“自然有感觉的稍长回复”压得太狠了

最该优先动的是：

- `long_short.jsonl`
- `long_history.jsonl`
- `tension.jsonl`

如果只让我给一句最直接的建议：

先把 `long_short` 移掉，把 `long_history` 和 `tension` 降下来，再重跑一版 DPO。  
这比单纯调推理参数更有希望把“感觉”找回来。
