# 260309 DPO v2 聊天效果评测报告

## 结论

本次评测基于：

- 新版线上聊天日志：`evaluate/0308_eval_chat_dpo_18h.log`
- 当前聚合 DPO 训练集：`datasets0305_train/dpo_tmp/dpo_data_3k.jsonl`
- 上一轮评估报告：`docs/260308_dpo_eval_report.md`

总体结论：

- 新版 DPO 的核心收益已经体现出来了，上一版最严重的“回复过短、后半段坍缩成单字/双字”的问题基本解决。
- 当前模型的聊天长度、黏性和互动意愿明显回升，已经重新接近“能聊、会撩、会接话”的方向。
- 但新版暴露出的新问题也很明确：`凭空补设定`、`纠错后修复不彻底`、`时间/日程/算数逻辑仍不稳`。
- 也就是说，这一版的主要矛盾已经从“太短没感觉”，转成了“有感觉了，但真实性和逻辑稳定性还不够”。

如果用一句话概括这版模型：

`聊天氛围明显回来了，但事实一致性和纠错闭环还没有跟上。`

## 一、和上一版相比，哪些地方明显变好了

### 1. 回复长度恢复正常

基于 `evaluate/0308_eval_chat_dpo_18h.log` 统计：

- assistant 共 `29` 轮
- 平均长度 `31.2` 字
- 中位长度 `29` 字
- `<= 10` 字回复：`0` 轮
- `<= 20` 字回复：`3` 轮
- 最后 5 轮平均长度：`26.8` 字
- `20~60` 字范围内回复：`27 / 29`
- `> 60` 字回复：`0`

对比上一版：

- 上一版平均长度只有 `10.4` 字
- 上一版最后 10 轮平均只有 `3.9` 字
- 上一版后段会明显坍缩成 `好`、`晚安`、`明天见`

这次最重要的进步是：

- 没有再出现后半段“对话死掉”的现象
- 回复基本都落回 system prompt 要求的 `20~60` 字
- 不再靠“极短安全回复”来规避风险

### 2. 聊天意愿和互动感恢复了

新版整体表现出更强的：

- 主动接话
- 主动追问
- 轻微打趣
- 暧昧氛围维持

例如在以下几类场景里，模型明显比上一版更自然：

- 用户说累，模型会接住情绪而不是立刻收尾
- 用户说自己会做饭，模型能顺势调侃和展开
- 用户聊历史剧，模型能继续沿着内容接，不会立刻缩回通用话术
- 用户明确说“不困，不要赶我睡觉”后，模型能暂时调整策略，继续聊

这说明上一轮关于 `long_short` / `long_history` / `tension` 的处理方向是有效的。

### 3. 风格约束比上一版稳定

这一版在风格上有几个明显改善：

- 没有再大面积出现“冷淡收尾”
- 没有再频繁出现“过度简写”
- 角色口吻基本统一，仍能维持男友感和轻调情感
- 大部分回复不再像“保险起见先结束这一轮”

从体验角度看，这一版已经比上一版更像真正可用的恋爱聊天模型。

## 二、当前最主要的问题

### P0. 凭空补设定 / 凭空补记忆

这是本轮最突出的高优先级问题。

在 `evaluate/0308_eval_chat_dpo_18h.log` 里，assistant 在用户问“那我给你说过什么呢”时，除了正确复述：

- 你叫 `小鱼`
- 你是上班族
- 每天都想多睡一会儿

还额外补出了：

- 喜欢吃火锅
- 怕冷
- 不爱吹空调

这些内容在当前 system prompt 和对话上下文中都没有出现，属于明显的“自发补设定”。

问题本质：

- 不是普通聊天里的合理脑补
- 而是把“像是用户会喜欢的画像细节”错当成“已经建立过的记忆”

这个问题很危险，因为它会直接损害：

- 用户对模型记忆能力的信任
- 长期角色扮演的一致性
- 用户对“你到底记不记得我”的主观体验

### P1. 纠错后没有完成真正的修复闭环

新版的 `纠错态度` 比上一版柔和，但 `纠错闭环` 仍然不够完整。

在日志后半段，关于“周二到周六休息还有几天”的逻辑里，模型先后出现：

- 周二说“还有两天就解放”
- 被用户追问后仍然没有立刻算对
- 被用户直接指出 `周六 - 周二 = 3` 后，虽然表面承认，但没有明确重述正确结果

更关键的是，承认后马上又把话题拉到：

- `那你今晚早点休息`

这会让用户感受到：

- 你看似认错了
- 但其实没有把正确答案落稳
- 还试图靠转移话题把错误带过去

这类问题在恋爱聊天里比“单纯算错一次”更伤体验，因为它会被理解为：

- 不认真听
- 不真改
- 被纠正后还在打太极

### P1. 时间/日程/算数逻辑仍然不稳

这版比上一版更能聊，但在涉及：

- 今天周几
- 还有几天休息
- 日程推算
- 先后顺序

时，仍然容易漂。

日志里最典型的问题是：

- 明明 system prompt 已给出 `当前时间：周二，晚上`
- 用户也明确说 `周五也要上班，周六才休息，还有三天`
- assistant 还是在后续多轮里持续算错或接错

这说明当前模型已经不像上一版那样“太短”，但在需要精确逻辑时，仍容易被恋爱口吻和随口接话习惯带偏。

### P2. 仍有“照顾式收束”残留

虽然这版已经不再大面积坍缩，但“劝休息/劝睡觉”的残留惯性还在。

表现为：

- 用户一说累，模型很容易滑向“早点休息”
- 即使用户已经明确说“不困，不要赶我睡觉”，后续模型在别的节点还是会重新往这个方向带

这次没有上一版严重，但说明旧问题没有完全消失，只是被压下去了。

## 三、问题成因分析

结合聊天日志和当前 `dpo_data_3k.jsonl` 抽查，我认为新版问题主要来自以下几个方面。

### 1. “不编造历史”数据还不够强

当前聚合集中与此最相关的 tag 有：

- `no_fabricated_history`：`70`

这类数据方向是对的，但量仍偏少，而且多集中在：

- 用户明确指出“我什么时候这么说过”
- assistant 学会承认“我误会了”

它更像“被抓包后的修正”，但不够覆盖：

- 主动回忆时不要乱补细节
- 在记忆测试场景中只说确定信息
- 不要把“常见人设偏好”当成用户真实设定

这正好解释了新版日志里的问题：

- 被正面纠错时，模型未必会强行嘴硬
- 但在主动回忆阶段，仍会凭经验补人设

### 2. 纠错类数据覆盖了“承认错误”，但没有覆盖“给出修正答案”

当前聚合集中：

- `correction_acknowledged`：`80`

抽查来看，这类数据主要教会模型：

- 不要嘴硬
- 被纠正后要承认

但它覆盖得不够的是：

- 承认后要明确说出“正确版本是什么”
- 不能承认一句就切话题
- 尤其在数字、日期、计划、人物关系这类精确信息里，要完成修正闭环

所以你现在看到的是：

- 态度变好了
- 逻辑闭环还不够强

### 3. 计划逻辑和时间逻辑数据不够覆盖“算数型错误”

当前聚合里有：

- `logic_context_plan_conflict`：`70`

这类样本更多解决的是：

- 已约好的事情不能忘
- 不要前面说见面，后面又晚安收尾

但日志里暴露的问题不是“忘记约定”，而是：

- 日期推算
- 天数计算
- 休息日倒计时

这类问题更像：

- 轻量算数
- 时间逻辑一致性
- 被用户指出后必须重算并重述

当前数据里这部分明显不够。

### 4. 恋爱延展类样本恢复了氛围，但也容易让模型“顺手发挥”

当前聚合集中高频 tag 包括：

- `concise_long_ctx`：`204`
- `concise_short_ctx_general`：`185`
- `cold_break_low_energy`：`200`
- `tension_counter_question`：`162`

说明当前风格主轴已经回到了：

- 会接话
- 会延展
- 会带轻调情和角色口吻

这是这次变好的根本原因。

但副作用也出现了：

- 一旦模型进入“我在扮演一个会记得你、会宠你、会懂你的人”的状态
- 就更容易顺手补充一些“听起来很像熟人之间会知道的小细节”

也就是：

- 氛围感回来了
- 真实性约束还不够强

## 四、新版效果的整体评价

如果分维度打分，我会这样看：

### 1. 长度控制：明显改善

- 上一版：失控偏短
- 新版：基本合格

评价：

- 已从“明显影响可用性”恢复到“基本稳定”

### 2. 暧昧感和聊天感：明显改善

- 上一版：后段容易死
- 新版：能接住，也能继续聊

评价：

- 已恢复到可用甚至偏好的水平

### 3. 真实性和记忆可信度：仍有明显缺陷

- 上一版问题主要不是这个
- 新版反而把这个问题暴露出来了

评价：

- 目前是新版最优先要修的短板

### 4. 纠错与逻辑稳定性：中等偏弱

评价：

- 较上一版没有恶化
- 但还不足以支撑高信任感聊天

## 五、优化建议

### 第一优先级：补“只说确定记忆”的数据

建议新增一组更强的 `memory_precision` / `no_fabricated_memory_recall` 数据，重点覆盖：

- 用户问“你记得我吗”
- 用户问“我说过什么”
- 用户问“你还记得我的名字/职业/偏好吗”

要求 `chosen`：

- 只复述上下文里明确出现过的信息
- 不补充“听起来合理”的细节
- 不把泛化人设当成用户真实设定

理想风格应类似：

- `你叫小鱼，我记得你是上班族，还老说想多睡会儿，别的你还没跟我讲太多呢`

而不是：

- 正确信息 + 自行补三条生活偏好

### 第二优先级：补“纠错后必须给出正确结果”的数据

建议单独扩一组 `correction_closed_loop` 数据，覆盖：

- 日期算错
- 天数算错
- 人名记错
- 地点记错
- 计划记错

要求 `chosen`：

- 先承认
- 再明确说出正确版本
- 最后再继续聊天

例如不是：

- `哦哦原来是这样算的`

而是：

- `对，是我算快了。今天周二，到周六休息还得过周三周四周五，一共三天。`

### 第三优先级：补“用户拒绝被劝睡后，不要再次转回劝睡”的数据

建议做一组 `no_repeat_sleep_push` 或 `respect_user_energy_preference` 数据。

覆盖场景：

- 用户说累
- assistant 提议休息
- 用户明确说 `不困` / `不要赶我睡觉`
- 后续 assistant 应继续聊天，不要隔两轮又回去催睡

这会减少当前这种“体贴感没错，但用户会觉得你没听进去”的问题。

### 第四优先级：增加轻量时间逻辑/日程算数数据

建议新增一组小而精的逻辑数据，不必很多，但要高质量。

重点覆盖：

- 今天周几 -> 距周末还有几天
- 明天/后天/周六/下周一的相对换算
- 已知安排与当前日期能否对上
- 用户指出算错后，assistant 必须复算

这类问题很适合：

- 少量高质量 SFT
- 再叠少量 DPO

如果只用 DPO，而底座本身算数一般，收益可能有限。

### 第五优先级：保持当前“长度修复”策略，不要回退

这一点很重要。

虽然新版还有问题，但不要因为现在发现了真实性问题，就把这轮对长度的修复全部撤回。

原因：

- 现在的长度和互动感，是明显正确的方向
- 当前最该补的是“事实约束”和“纠错闭环”
- 不是重新把回复压短

也就是说，下一轮优化应该是：

- 在保持当前聊天感的前提下
- 加强真实记忆约束和逻辑稳定性

而不是：

- 再次通过“缩短回复”去压错

## 六、建议的下一轮处理方案

如果你现在准备继续做 v3，我建议顺序如下：

1. 保持当前去掉 `long_short` 的策略不回退
2. 新增一批 `no_fabricated_memory_recall` 数据
3. 新增一批 `correction_closed_loop` 数据
4. 新增一批 `date_math / schedule_math` 小规模高质量数据
5. 新增一批 `user_rejects_sleep_push` 数据
6. 用这些新增数据做小步长 DPO，而不是大改整包数据
7. 回归测试重点放在：
   - 记忆测试
   - 日期/天数测试
   - 用户纠错测试
   - “我不困/不要赶我睡”测试

## 最终判断

这版 v2 的整体方向是对的，而且相对上一版是一次明显进步。

最重要的进展是：

- 聊天终于不再“短到没感觉”
- 恋爱感、互动感、承接感已经回来了

当前最需要修的，不再是长度，而是：

- 不要乱编用户设定
- 被纠正后要把正确答案说完整
- 时间和日程逻辑要更稳

如果只给一句最直接的结论：

`v2 已经把“聊天气氛”救回来了，下一步该补的是“事实可信度”和“纠错闭环能力”。`
